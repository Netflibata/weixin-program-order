微信云开发点餐小程序
一、项目整体功能介绍（最终成品）
本小程序为云开发点餐系统，无需后端服务器，全程依托微信云开发部署，功能完整、权限逻辑严谨，适配普通用户与管理员双端使用。
1. 用户端功能
- 菜品页面：支持分类筛选、菜品展示、加入购物车，突破云开发20条菜品展示上限
- 购物车页面：菜品数量增减、自动核算总价、清空购物车、提交订单
- 我的订单页面：展示平台所有用户订单，仅本人下单订单可删除，他人订单仅可查看、无法操作
2. 管理员端功能
- 菜品管理：支持菜品上传、菜品信息编辑
- 订单管理：后台查看全平台用户订单，拥有最高权限，可删除任意用户的任意订单
3. 核心权限逻辑
- 普通用户：全员可见全部订单，仅可操作（删除）自己的订单
- 管理员：无任何权限限制，可查看、删除所有用户订单
- 所有订单自动绑定用户唯一openid身份标识，从底层杜绝篡改、删除他人订单的问题
二、前置环境准备（必做）
1. 安装微信开发者工具，注册小程序账号，配置合法小程序AppID
2. 开通小程序云开发环境，免费版环境可满足全部使用需求
3. 项目根目录 project.config.json 配置云函数根路径，确保工具可正常识别、上传云函数
4. 关联对应云开发环境，开发者工具顶部选择已创建的云环境，避免环境匹配失败
三、云函数部署流程（核心必做、对应文件名称）
项目共2个自定义云函数，存放目录：cloudfunctions 文件夹，部署统一操作：右键云函数文件夹 → 上传并部署：云端安装依赖。
1. login 云函数（文件夹名称：login）
包含核心文件：index.js、package.json
核心作用：规避前端直接获取openid的报错问题，通过云端安全获取用户唯一身份标识，统一下单、订单匹配的身份依据，解决下单失败、订单不匹配问题。
2. deleteOrder 云函数（文件夹名称：deleteOrder）
包含核心文件：index.js、package.json
核心作用：突破前端数据库权限限制，专供管理员后台使用，实现管理员无限制删除全平台任意订单，区分普通用户与管理员权限。
四、数据库配置规则（关键配置）
进入云开发后台-数据库，手动创建两个核心集合，无需修改文件，纯后台配置：
- dishes 集合：存放所有菜品数据
- orders 集合：存放所有用户订单数据
1. dishes 菜品集合权限
开发调试阶段：开放全部读写权限，方便上传、编辑、展示菜品，避免权限拦截导致菜品加载、修改失败。
上线正式阶段：可收紧权限，仅管理员可写入修改，所有用户可读。
2. orders 订单集合权限
开发调试阶段：全开读写权限，彻底解决下单失败、订单读取为空、新增订单被拦截的问题。
上线安全阶段：配置精细化权限，所有用户可读取全部订单，仅订单创建者可删除、修改自身订单，保障数据安全。
五、全局页面配置（对应文件：app.json）
修改项目根目录 app.json 全局配置文件，完成两项核心配置，否则页面、底部导航无法正常显示：
1. 页面注册：将所有业务页面（含新增的我的订单页面）注册到pages数组，小程序方可识别页面路径
2. 底部Tab配置：配置底部导航栏，展示菜品菜单、购物车、我的订单、管理员四个入口，设置图标、选中颜色、页面跳转路径
六、核心页面功能说明与对应文件名称
1. 购物车下单页面
对应页面目录：pages/cart/
核心生效文件：cart.js（主逻辑文件）、cart.wxml、cart.wxss
功能：加载本地购物车数据、实时计算总价、增减菜品数量、清空购物车、提交订单。
关键修改点：重写下单逻辑，废弃前端错误openid写法，调用login云函数获取用户身份，自动绑定订单信息、下单成功跳转订单页。
2. 我的订单页面（新增核心页面）
对应页面目录：pages/myOrder/
全套生效文件：myOrder.js、myOrder.wxml、myOrder.wxss、myOrder.json
功能：加载平台全部用户订单，按最新下单时间置顶排序，展示订单号、下单时间、总价、菜品明细。
权限适配：自动匹配当前用户openid，本人订单显示删除按钮，他人订单仅展示文字提示、无操作入口，完美适配需求。
刷新逻辑：页面每次切换显示时，自动重新拉取最新订单数据，确保新下单订单实时展示，无缓存延迟。
3. 管理员订单管理页面
对应页面目录：pages/orderList/
核心生效文件：orderList.js（修改删除订单逻辑）
功能：后台展示全平台所有订单，依托deleteOrder云函数实现删除功能。
权限优势：不受前端数据库权限限制，可任意删除所有用户的订单，实现管理员最高管理权限。
4. 菜品首页分页加载
对应文件：pages/index/index.js
作用：突破云开发20条菜品限制，加载全部菜品数据
5. 管理员后台主页
对应目录：pages/admin/
作用：管理员登录入口、功能导航入口
6. 菜品上传/编辑页面
对应目录：pages/dishUpload/、pages/dishEdit/
作用：管理员上传、修改菜品信息
七、菜品数量上限解决方案
对应文件：index.js、orderList.js
项目已全局配置菜品分页加载逻辑，针对云开发默认20条数据展示限制做了适配优化，可完整加载全部上传菜品，无数量截断、无数据丢失，无需二次修改代码。

1. 清理开发者工具全部缓存，重新编译项目，清除旧数据缓存干扰
2. 登录管理员后台，上传测试菜品，完善菜品分类信息
3. 普通用户端选择菜品、加入购物车，提交订单，验证下单成功并自动跳转订单页面
4. 验证订单页面功能：可查看全部订单，仅自身订单可删除，他人订单不可操作
5. 登录管理员后台，验证可查看、删除任意用户订单，权限区分正常
九、常见报错问题与对应修复文件
1. 提交订单一直下单失败
涉及文件：cart.js、login云函数、数据库orders权限
核心原因：前端原生openid获取写法报错、数据库权限拦截新增订单、云函数未部署/未关联环境。
解决办法：部署login云函数、修改cart.js下单逻辑、订单集合调试阶段全开读写权限。
2. 下单成功，我的订单页面不显示新订单
涉及文件：myOrder.js
核心原因：用户openid获取方式不统一、页面缓存未刷新、数据加载时序异常。
解决办法：替换最新myOrder.js、统一云函数获取openid、开启页面自动刷新。
3. 管理员无法删除订单
涉及文件：orderList.js、deleteOrder云函数
核心原因：deleteOrder云函数未部署、未对接页面删除方法。
解决办法：部署deleteOrder云函数、更新orderList.js删除逻辑。
4. 云环境报错、无可用云环境
涉及文件：project.config.json、开发者工具云环境配置
核心原因：项目未关联云环境、云函数根目录未配置。
解决办法：配置云函数根目录、手动关联云环境、重启开发者工具。
